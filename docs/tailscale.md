# Tailscale: память на роутере

Памятка: как уменьшить потребление ОЗУ у Tailscale на OpenWrt.

Tailscale — Go-приложение. На роутере процесс `tailscaled` занимает
порядка **90–100 МБ RSS** (замер на GL-MT6000: ~97 МБ). На роутере
с 1 ГБ это терпимо, а на 256 МБ — почти половина памяти, поэтому там
настройка обязательна.

### Когда нужно

| ОЗУ | Нужно? |
|---|---|
| 128–192 МБ | обязательно |
| 256 МБ | обязательно |
| 512 МБ | рекомендуется, если не хватает памяти |
| 1 ГБ и больше | обычно не требуется |

Скрипт определяет объём ОЗУ сам и пишет рекомендацию перед меню.

Скрипт `scripts/tailscale-tune.sh` добавляет в `/etc/init.d/tailscale`
три параметра Go-окружения:

| Параметр | Что делает |
|---|---|
| `TS_NO_LOGS_NO_SUPPORT=true` | отключает отправку диагностических логов на `log.tailscale.com` |
| `GOMEMLIMIT=35MiB` | мягкий лимит памяти Go-рантайма |
| `GODEBUG=madvdontneed=1` | агрессивнее возвращать освобождённую память ОС (поведение старых версий Go) |

Вставляются после строки
`procd_set_param env TS_DEBUG_FIREWALL_MODE="$fw_mode"`.
Скрипт идемпотентен: повторный запуск не создаёт дубликатов.

## Как применить

Одна команда на роутере по SSH от root:

```sh
wget -O /tmp/tailscale-tune.sh https://raw.githubusercontent.com/k4reon/k4reon-mihomo-rules/main/scripts/tailscale-tune.sh && sh /tmp/tailscale-tune.sh
```

Дальше скрипт покажет diff и спросит:

```
Что сделать?
  1) Применить (без логов, GOMEMLIMIT=35MiB, GODEBUG)
  2) Откатить
  0) Выйти
Выбор:
```

Enter — применить. Скрипт сделает бэкап `/etc/init.d/tailscale.bak`,
перезапустит службу и покажет переменные и RSS.

## Без вопросов

```sh
sh /tmp/tailscale-tune.sh --yes       # применить
sh /tmp/tailscale-tune.sh --dry-run   # только показать diff
sh /tmp/tailscale-tune.sh --restore   # вернуть исходный init-скрипт
```

## Проверить память

До и после:

```sh
p=$(pidof tailscaled | awk '{print $1}')
grep VmRSS /proc/$p/status
tr '\0' '\n' < /proc/$p/environ | grep -E 'TS_NO_LOGS|GOMEMLIMIT|GODEBUG'
```

## Важно

- `GOMEMLIMIT=35MiB` — **мягкий** лимит: он не ограничивает RSS жёстко,
  а заставляет сборщик мусора работать раньше. Слишком низкое значение
  повышает нагрузку на CPU — сравните RSS и нагрузку до/после;
- `TS_NO_LOGS_NO_SUPPORT` отключает именно отправку логов разработчикам,
  локальные логи и работа сети не затрагиваются;
- `GODEBUG=madvdontneed=1` актуален для старых версий Go; в современных
  (Tailscale 1.98 использует Go 1.26) это поведение уже по умолчанию,
  параметр остаётся для совместимости и ничего не ломает;
- обновление пакета Tailscale заменяет `/etc/init.d/tailscale` — после
  обновления скрипт нужно запустить заново;
- откат: `sh tailscale-tune.sh --restore` (вернёт `.bak` и перезапустит).
